### Phase A — RAG foundation (new package `omni/llm/rag/`)

**A1. `omni/llm/rag/chunker.py`** (~120 LOC)
- `chunk_news_article(row: pd.Series) -> list[Chunk]` — one chunk per article (title + description), or two if description >800 chars
- `chunk_filing_section(text: str, doc_type: str) -> list[Chunk]` — section-aware (`Item 1A`, `Item 7`, etc.) for 10-K/10-Q
- `chunk_transcript(text: str) -> list[Chunk]` — speaker-turn aware for earnings calls
- `Chunk` dataclass: `text, ticker, asset_class, source, doc_type, date, chunk_index, payload_extras`

**A2. `omni/llm/rag/store.py`** (~180 LOC)
- `RAGStore` wraps `QdrantClient(path="data/rag/qdrant")` (on-disk persistent local mode)
- One Qdrant collection per `(asset_class, doc_type)` combination — `india_news`, `us_news`, `us_filings_10k`, `us_transcripts`, etc. (lazy-created)
- Vector dim = 1024 (Nemotron), distance = COSINE
- Payload schema: `{ticker, asset_class, source, date_iso, doc_type, chunk_index, text, sent_score?, url?}`
- Methods: `upsert(chunks)`, `search(collection, query_vec, ticker_filter, date_range, top_k)`, `count()`, `purge_older_than(days)`
- Batch upsert (256 chunks/batch) with retry

**A3. `omni/llm/rag/embedder.py`** (~80 LOC)
- Thin wrapper around `omni.llm.embed_nemotron.embed()` adding:
  - In-process LRU (functools, 4096 entries) so repeated chunks during ingest don't re-hit the API
  - Disk cache via `LLMCache` (per-text key) so embeddings persist across restarts
  - Auto-batching to 96 inputs per request (Nemotron limit)
  - `is_zero` check + skip for failed embeds (caller logs)

**A4. `omni/llm/rag/retriever.py`** (~200 LOC)
- `HybridRetriever` with three stages:
  1. **BM25 (local sparse)** — `rank_bm25.BM25Okapi` built on filtered chunk subset (by ticker + date window). Top-50 results
  2. **Dense (Qdrant)** — embed query via Nemotron, search the relevant collection with same filters. Top-50 results
  3. **Reciprocal Rank Fusion** merges the two ranked lists into top-30
  4. **Reranker** — `BAAI/bge-reranker-base` loaded on `cuda:0` (lazy import, falls back to `cpu` if torch.cuda not available). Re-scores top-30 query/doc pairs, returns top-K (default 5)
- BM25 corpus is rebuilt per-query from the current ticker+date filter (fast — typically <1k chunks)
- `retrieve(query, *, ticker, asset_class, doc_types, date_range, top_k=5) -> list[RetrievedChunk]`

**A5. `omni/llm/rag/prompts.py`** (~60 LOC)
- `build_signal_prompt(*, ticker, name, asset_class, regime, pillars, proba_up, direction, conviction, retrieved_chunks) -> str`
- System message: "Answer using ONLY the provided context. Cite each claim [N]. If context is insufficient, say so. Never invent numbers."
- Context block format: `[1] (NVDA, 2024-11-15, Reuters) "Nvidia reported Q3 revenue of $35.1B..."`
- Question section with structured pillar breakdown
- Length budget: ~80 words, 3-4 sentences (matching existing why-text contract)

**A6. `omni/llm/rag/validators.py`** — anti-hallucination layer (~150 LOC)
- `extract_numbers(text) -> list[str]` regex for `\$?\d[\d,]*\.?\d*%?` patterns
- `numeric_grounding_check(answer, retrieved_chunks) -> tuple[bool, list[str]]` — every number in answer must appear in at least one retrieved chunk; returns (is_grounded, unsupported_numbers)
- `citation_check(answer) -> tuple[bool, set[int]]` — answer must contain `[N]` markers; checks all referenced indices are in the retrieved set
- `claim_grounding_score(answer, retrieved_chunks) -> float` — sentence-level: split answer into sentences, embed each, compute max cosine vs retrieved chunks. Score = mean across sentences. Threshold 0.55 pass
- `validate(answer, retrieved_chunks) -> ValidationResult{is_safe, score, issues, sanitized_text}` — runs all three checks. If `unsupported_numbers` found, the offending numeric tokens are replaced with `[unverified]`. If grounding score < 0.55 OR no citations, returns `is_safe=False` with reason

**A7. `omni/llm/rag/pipeline.py`** (~140 LOC)
- `RAGPipeline.answer(question, *, ticker, asset_class, doc_types, date_range, top_k=5) -> RAGResponse`
- Steps: retrieve → build prompt → route via `omni.llm.router` to a configurable task → validate → return `{text, citations, retrieved, grounding_score, is_safe, fallback_used}`
- On `is_safe=False`: try once more with temperature=0.1 (more conservative); if still unsafe, return deterministic refusal: `"Insufficient grounded information to explain this signal."` + the deterministic-fallback why-text (existing path)

### Phase C — Anti-hallucination layer details (covered above in A6)

This is integrated into the pipeline — no separate phase. Specifically:
- **Numeric guardrail** (A6 step 1+2): regex extracts numbers, verifies presence in retrieved chunks, replaces unverified ones with `[unverified]`
- **Citation requirement** (A6 step 3): rejects answers without `[N]` markers
- **Sentence-level grounding score** (A6 step 4): embed each answer sentence, max-cosine vs retrieved, mean across sentences. Threshold 0.55 (tunable in YAML)
- **Refusal flow** (A7): unsafe → retry with temp=0.1; still unsafe → deterministic fallback with explicit "insufficient evidence" caveat
- **Self-consistency** (deferred): not in this batch — would 3× the cost. Document as future option

**Edge cases checked in design:**
- Nemotron rate limit (429): fall back to zero vectors, validator catches and uses deterministic
- bge-reranker-base CUDA OOM: catch, fall back to CPU, log warning
- Empty retrieval (filter too narrow): pipeline returns deterministic fallback with explicit "no recent news matched" message
- All-zero embeddings (API key missing): `embed_nemotron.is_zero` check skips dense search, falls back to BM25-only
