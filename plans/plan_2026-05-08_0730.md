2. Create `omni/lake/` package:

   - `omni/lake/io.py` — `read_prices(ticker, ac)`, `append_prices(...)`, `last_date_in_lake(...)`, `read_fundamentals_asof(...)`, `read_news_window(...)`. All parquet via pyarrow.

3. New script `scripts/backfill_universe.py` — CLI wrapper, takes `--asset-classes`, `--limit`, `--lookback-years`, `--mode {full,incremental}`. Logs progress with tqdm.
4. Switch `omni/ondemand/lookup.py` price/fundamentals fetch path to **lake-first, live-fallback**:

   - else live-fetch and write back to lake on the way out
5. New `scripts/build_training_set.py` — reads from lake, builds the pooled training frame for trainer (no live API calls). Writes `data/lake/training_set_5d.parquet`.

### Step 2 — High-impact features
Add to `omni/features/`:
- `cross_sectional.py` — `pe_pct_in_sector`, `momentum_pct_in_class`, `vol_pct_in_class`. Computed at frame level (groupby asset_class + date).
- `insider.py` — parse Form 4 XBRL via `python-edgar` lib; compute `insider_buy_dollars_30d`, `insider_sell_dollars_30d`, `insider_net_30d`, `insider_net_90d`. Feeds from `data/lake/edgar/form4.parquet`.
- `short_interest.py` — pulls FINRA bi-weekly Reg SHO CSV, computes `short_pct_float`, `days_to_cover`, `short_change_2w`.
- `options_flow.py` — Cboe daily volume CSV → `put_call_ratio`, `equity_put_call_ratio`, `oi_change_5d`.
- `earnings.py` — yfinance earnings history → `eps_surprise_pct`, `days_until_earnings`, `post_earnings_drift_5d`.
- `sector_rs.py` — `stock_ret − sector_etf_ret` over 5/20/60 days; needs sector ETF mapping in `config/sector_map.yaml`.
- `sentiment_z.py` — z-score sent_mean against the ticker's own 30d rolling history.
- `regime_interactions.py` — feature × regime crosses for top-10 features (auto-named e.g. `rsi_14_x_bull`).
- `vol_adjusted_momentum.py` — `ret_20d / realized_vol_20d`.

Wire all into `features_inline.py` so they're computed both for training (lake-mode) and live prediction.

### Step 3 — Recency-weighted training + cleaner targets
- New `omni/models/training_utils.py`:
  - `recency_weights(dates, half_life_years=5)` — exponential half-life weights.
  - `magnitude_weights(fwd_returns)` — weight by `|fwd_ret|` so big moves matter more.
  - `top_quartile_target(fwd_returns, lookback_window=252)` — boolean: was it in top quartile of recent rolling distribution.
- Modify `walkforward_fit` to accept `sample_weight` array.
- Trainer offers `--target-mode {sign,sigma_filtered,top_quartile}`.

### Step 4 — Optuna hyperparameter tuning
- New `scripts/tune_universal_model.py`:
  - 200 Optuna trials with TPESampler.
  - Search space: `max_depth ∈ [3,8]`, `learning_rate log[0.01,0.1]`, `n_estimators ∈ [200,800]`, `subsample ∈ [0.6,1.0]`, `colsample_bytree ∈ [0.6,1.0]`, `min_child_weight ∈ [1,20]`, `reg_alpha`, `reg_lambda`.
  - Objective: mean walk-forward AUC across 8 folds.
  - Best params written to `config/xgb_best_params.yaml`.
- Trainer reads `xgb_best_params.yaml` if present, else falls back to defaults.

### Step 5 — 3 horizon models (1d / 5d / 21d)
- Refactor `model_registry.py`:
  - `UniversalModel` becomes `UniversalModelSet` carrying a dict `{horizon_days: model_bundle}`.
  - File layout: `data/models/universal_{horizon}d.joblib` plus shared `metadata.json`.
  - Backwards-compat: `load_5d()` shim returns the 5d bundle for old callers.
- `scripts/train_universal_model.py`: outer loop over `[1, 5, 21]`, calls `walkforward_fit(target=f"fwd_dir_{h}d")` for each, saves into the set.
- `predict.py`: calls all 3 models on the same feature row, returns a `dict[horizon → proba_up]`. Card gets new fields `proba_up_1d`, `proba_up_5d`, `proba_up_21d`. Horizon table in UI uses these directly instead of extrapolation.

### Step 6 — Ensemble specialists blended by regime
- New `omni/models/specialists.py`:
  - Trains 4 separate models on disjoint feature subsets: tech-only, fund-only, sent-only, macro-only.
  - All share the same target (5d direction first, then 1d/21d if Step 5 done).
  - Each saved to `data/models/specialist_{kind}_{h}d.joblib`.
- New `omni/ensemble/blend.py`:
  - `blend_predictions(preds_by_specialist, regime, regime_proba)` — regime-conditional weights from `config/regime_weights.yaml`. e.g. in bull: tech 0.4, sent 0.3, macro 0.2, fund 0.1; in bear: macro 0.5, fund 0.3, ...
  - Soft blend using regime probabilities (not hard label) so transitions are smooth.
- Predict path: optional `--use-ensemble` flag in card; defaults to ensemble once trained.

### Step 7 — Prediction logging + drift monitor + auto-retrain
- `omni/monitoring/predict_log.py`: every `predict_ticker()` call appends to `data/lake/predictions/{date}.parquet` with: ticker, asof, proba_up_h, blended_p, conviction, model_version_hash.
- `scripts/daily_backtest.py` (cron-ready):
  - Reads predictions older than max horizon (e.g. all 5d-old predictions and check realized 5d return).
  - Computes realized AUC, hit rate, Brier score per horizon, per asset_class, last 30d / 90d / all-time.
  - Writes `data/lake/monitoring/realized_metrics.parquet`.
  - Alert (log warning + write `monitoring/alert_*.txt`) if rolling 30d AUC drops below threshold (e.g. 0.51) or Brier degrades by > 10%.
- New dashboard tab "Monitor" reading the monitoring parquet — shows AUC over time per horizon with confidence bands.
- `scripts/retrain_if_drift.py` — checks alerts and triggers `train_universal_model.py` if drift detected.

**Common-failure-pattern checks before marking each step done:**
- Step 1: parquet schema consistency across tickers (column dtypes), idempotency under re-run, no race on concurrent writes.
- Step 2: feature value ranges sane (no infinities, no all-NaN columns), feature leakage (any feature using future data), missing-value handling.
- Step 3: weights sum to non-zero, target distribution not collapsed (e.g. all-zero after sigma filter).
- Step 4: trial AUCs monotonically improving on average; no overfitting to val (track gap between train AUC and val AUC).
- Step 5: per-horizon target coverage (drop rows where target NaN), feature columns aligned across the 3 trained models.
- Step 6: specialist models all trained on the SAME row set (no implicit row drops differing across specialists), regime probabilities sum to 1.
- Step 7: timestamp parsing, time-zone consistency between log entries and realized prices.

## Risk notes

- **Disk usage**: 500 tickers × 15 yr × ~3,500 daily bars × 8 cols ≈ ~300 MB compressed. Trivial.
- **API rate limits during full backfill**: yfinance throttles after ~2000 reqs/hr. Build with concurrency=4, retry-with-backoff.
- **MiniMax free tier quota**: undocumented but typically ~50 req/day per OpenRouter account. The Groq fallback handles overflow.
- **Optuna parallelism**: with our existing single-machine training, 200 trials × ~30s each = ~100 min. Acceptable for a one-time tune.
- **Specialists overfitting per-regime**: blend with shrinkage (regime weights pulled toward equal-weight prior) to prevent one specialist dominating a transient regime.
- **Backwards compat**: keep `model_registry.load()` (no args) returning the 5d bundle so existing call sites don't break during the Step 5 migration.
- **Time scope**: Steps 1+2 alone are ~80% of the AUC lift available. If you want to stop early, stop after Step 4 (data + features + recency + tuning); you'll be at AUC ~0.56-0.57 with a much more robust system. Steps 5-7 add structure + monitoring but smaller AUC lift.
